# 事务原理
## 事务
```
前提:并发连接访问
多个连接并发连接访问,多个连接并发执行,执行期间,造成切换等操作,可能造成数据混乱


事务就是解决上面连接并发执行问题


事务的控制语句

-- 显示开启事务
start transaction | begin
-- 提交事务,使得已对数据库做的所有修改持久化
commit
-- 回滚事务 ,测小正在进行的素有未提交的修改
rollback

-- 创建一个保存点 一个事务可以有多个保存点
savepoint identifier

--删除一个保存点
release savepoint identifier

-- 事务回滚到某个保存点
rollback to [savepoint] identifier




事务的声明周期
1.
begin
commit


2.begin
rollback

```
## ACID 特性
```
1.原子性(undolog 回滚事务)
    要么成功 要么失败
2.一致性
    事务执行前后,数据库从一个一致性状态到另一个一致性状态
3.隔离性(锁+mvcc)
    防止多个并发事务交叉执行导致数据不一致
4.持久性(redolog )
    DML 对数据库变更 都要写到数据库持有化




undolog:
    1.记录DML操作,用于回滚通过逆运算
    2.记录事务DML提交的版本信息

redolog:
    1.事务提交后记录DML 记录对应物理页的修改内容



binlog:二进制日志 
    1.记录DML操作,用于主从复制,数据恢复



commit
    redolog 刷盘
    binlog 刷盘




note:
    innodb 中 一个语句也是事务 不需要加begin commit


```
## 隔离级别
```sql
note:隔离级别最高,并发效率是最低的

锁+mvcc

写操作:
    update delete insert



目的:提升并发性能


写操作:全部都加X锁


read uncommmitted 读未提交
    读:不做任何处理(可能读取到其他事务未提交的数据)
    写:自动加X锁


    脏读





例:

CREATE TABLE account (
    id INT PRIMARY KEY,
    balance INT
) ENGINE=InnoDB;

INSERT INTO account VALUES (1, 1000);



两个事务同时执行。


A:
BEGIN;

UPDATE account
SET balance = 500
WHERE id = 1;

-- 暂时不提交


SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;

BEGIN;

SELECT balance FROM account WHERE id = 1;// 读取的结果500




如果此时事务A回滚
ROLLBACK;



事务B之前读取的就是脏读






read committed 读已提交 (大部分数据库默认隔离级别)
    读:mvcc 读取最新版本的的行数据
    写:自动加X锁

     

    幻读


例如:
    CREATE TABLE users (
    id INT PRIMARY KEY,
    age INT
) ENGINE=InnoDB;

INSERT INTO users VALUES
(1, 20),
(2, 25),
(3, 30);


事务A

begin

select * from user;


此时读取了
1 20
2 25
3 30


事务B

begin

BEGIN;

INSERT INTO users VALUES (4, 28);

COMMIT;



事务A


select * from user;

此时读取了
1 20
2 25
3 30
4 28


同一个事务 两次查询的记录不一样 就出现幻读
commited read 每次读取都读取最新版本



repeatable read 可重复读 (mysql 默认隔离级别)
    读:mvcc 读取事务开启前的版本的行数据
    写:自动加X锁


读取的都是begin 之前版本的数据

select 无论怎么样读都是一致的




serializable 串行化
    读:自动加s锁(next-key lock)
    写:自动加X锁



```

## 不通的隔离级别并发异常
```
read uncommmitted
    脏读,不可重复读,幻读


read committed
    不可重复读,幻读

repeatable read
    幻读


脏读:
    一个事务读取到另一个事务未提交事务修改的数据

不可重复读:
    一个事务内两次读取同有一个数据不一样

幻读:
    一个事务内两次查询同一个条件不一样,查询到不同的记录条数


// for update 加锁
select * from user whre id > 2 for update


```
## mvcc
```
一致性非锁定读

read_view:
    m_ids:创建read_view 启动未提交的事务id列表
    min_trx_id :场景read_view 启动未提交的最小事务id
      id 64bits 自增 
    max_trx_id :场景read_view 预分配给下一个未开启事务id

    creator_trx_id:创建read_view的事务id    
            read_view创建时机
                1.事务开启
                2.select 创建



聚集索引记录的隐藏列
    trx_id:
        1.事务修改记录是 trx_id 记录修改事务id
        2.dml 操作是加锁的不管什么隔离级别

        note:
             行的隐藏列记录了那个事务trx_id 修改该行
             并且加锁
             只能被一个事务修改


    roll_pointer
        事务修改记录是  将旧记录写入 undo log,该指针指向旧版本记录





事务可见性问题
    1.事务可以看见事务本身的修改
        begin
        select *
        update
        select *   // 在同一个事务只能可以看见自己的修改后的值


    2.事务间的可见性
        2.1 trx_id < min_trx_id 说明 在begin 之前 trx_id 已经提交 可见
        2.2 trx_id >=max_trx_id
            max_trx_id 表示 当前begin 之后写的 
            不可见
        2.3 trx_id >= min_trx_id && trx_id < max_trx_id
            trx_id in m_id 未提交 不可见

            trx_id not in m_ids 提交 可见






read commited
    每次读取都生成新的read_view


repeatable read
    在事务开始的时候创建read_view



```

## 锁
```
全局锁(锁数据库)
    flush tables with read lock
    unlock tables

    用于全库备份

表级锁

    lock tables table_name [write/write]
    unlock tables

    元数据锁(MDL)
        数据修改的时候,不能让其他连接修改表结构

    意向锁
        目的:快速判断表里是否有锁


    auto-inc 锁
        auto increment 自增约束
        insert 数据的时候会使用 auto-inc 锁(表级)

行级锁

    record lock (记录锁)
            S 共享锁
            X 排他锁

    间隙锁(gap lock)
        repeatable read 隔离级别下,防止幻读
        间隙锁 锁住的是 索引记录的间隙
         防止其他事务插入间隙中的记录


next-key lock
 repeatable read

    记录锁 + 间隙锁
    防止幻读





```
