# 锁
## 分类
```
1.全局锁
    锁定数据库中所有表
2.表级锁
    每次操作锁住整张表
3.行级锁
    每次操作锁住对应行数据

```
### 全局锁
```
使用场景:全库逻辑备份


1.flush tables with read lock;

2.数据备份 mysqldump -uxxx -pxxx db_name> db_name.sql

3.unlock tables;

可以保证数据的一致性


全局锁存在的问题:
1.全局锁的锁的粒度太大 如果在主库中备份 加上全局锁导致在备份期间业务停摆
2.如果在从库中加上全局锁 会导致从库不能同步主库过来的二进制日志,会导致主从延迟


在InnodDB中 可以在备份中加上 --single-transaction 参数 来完成不加锁来完成数据备份 底层使用快照读来实现备份

```
### 表级锁
```
表锁
    read lock

    write lock

lock tables table_name [read/write];
unlock tables/客户端连接关闭



lock tables tb_name read;
    每个客户端都能读
    所有客户端不能写


lock tables tb_name write;
    其他客户端不能读和写会被阻塞
    当前加锁的客户端 能读也能写

元数据锁(meta data lock,MDL)
    无需显示的使用 在访问一张表的时候会自动的加上
    在表上有活动事务的时候不可能对元数据进行写入操作
    

    元数据:简单理解就是表结构


    
    Mysql 5.5 就加入了MDL
        当我们对数据进行增删改查的时候就会对元数据添加读锁
        当我们对表结构进行修改的时候会为MDL 加上写锁 排他锁


select delete update  insert MDL 读锁

alter table MDL 写锁


// 源对象锁查询

意向锁

主要解决问题:Innodb 行锁和表锁的冲突问题


例
1.
A 
  begin 
  update 给这行加上了行锁


B 向给改表加上 lock tables tb_name write;
   
   必须判断该表上有没有行锁 没有才能加上表锁 否则会冲突
    
   每一行都检测是否有行锁



这样做太浪费效率 诞生意向锁


行锁+改表添加上意向锁

表锁 判断是否有意向锁 判断能否加上表锁




意向共享锁(IS)
    select ...... lock in share mode


意向排他锁(IX)
    select ...... for update
    delete
    insert
    update


意向共享锁 和 表锁读锁 兼容

意向排他锁 和任何表锁互斥

```

### 行锁
```
InnoDB 数据是基于索引组织的,行锁是通过对索引上索引项加锁实现的

1.行锁(Record Lock),锁定的是具体某一行
   read commited
   repeatble read 



select  ;不加任何锁

共享锁(S)
    
    select ...... lock in share mode
排他锁(X)
    select ...... for update
    delete
    insert
    update



排他锁获取 其他session 不能获取共享锁和排他锁



note:
Innodb 的行锁是针对索引加的锁，不通过索引检索数据将对表中的所有数据加锁,升级为表锁



2.间隙锁(Gap Lock),锁定记录间隙 不包括该记录，确保记录间隙变,防止其他事务insert 记录 产生幻读 
   
   repeatble read 

    
 间隙:两个记录之间的间隙


默认情况下,Innodb 在RR事务隔离级别运行,InnoDB使用next-key 锁惊醒搜索和索引扫描防止幻读


1.索引等值查询(唯一索引),给不存在的记录加锁,优化为间隙锁

2.索引上等值查询(普通索引),从右遍历最后一个值不满足需求是next key lock 退化为间隙锁

普通索引非唯一 需要遭到 当前普通索引 向右第一个不等于该值的位置 该间隙设置上间隙索引 防止 相同的值插入




3.索引的范围查询(唯一索引) 会访问到第一个不满足条件的第一个值为止




3.临键锁(Next-Key Lock)
    行锁+间隙锁
    锁住数据并锁住前面的间隙 RR 支持
    repeatble read 



note:
   1.间隙锁唯一的目的是防止其他事务插入间隙
   2.间隙锁可以共存
   



```
